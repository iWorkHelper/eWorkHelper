# 批量文本过滤

## 功能概览

Excel Ribbon 的 `eWorkHelper` Tab 在“数据工具”Group 中提供“批量过滤”按钮。用户先选择目标列中的单元格，再通过窗口输入每行一个条件并选择匹配方式。

支持以下不区分大小写的文本匹配：

- 等于：单元格完整文本与任一条件相等时保留。
- 不等于：单元格完整文本与所有条件均不相等时保留。
- 包含：单元格文本包含任一条件时保留。
- 不包含：单元格文本不包含任何条件时保留。

“包含”为默认模式。

## 条件处理

- 输入按换行拆分。
- 去除每行首尾空格并忽略空行。
- 使用精确文本比较去除完全重复的输入条件。
- 除首尾空格外，不改写用户条件。
- 单元格值通过当前区域性转换为文本，匹配使用 `OrdinalIgnoreCase`。

## 筛选区域

目标列固定为启动功能时的 `ActiveCell.Column`。

### Excel 表格

活动单元格位于 ListObject 时，复用表格的 `ListObject.Range` 和目标 `ListColumn.DataBodyRange`，并确保原生筛选箭头可用。

### 已有 AutoFilter

工作表已有 AutoFilter 时，只有目标列位于现有筛选区域内才继续；否则停止且不重建、不清除用户已有筛选区域。

### 普通区域

工作表没有 AutoFilter 时，通过 `Application.InputBox(Type: 8)` 要求用户选择单一标题行。取消不会修改工作表。CurrentRegion 只用于确定列边界和数据底部，最终筛选范围第一行严格使用用户选择的标题行；目标列必须位于最终区域中。

## 应用与清除

- 数据列通过一次 `Value2` 读取进入内存。
- 匹配值去重后，以完整值数组和 `xlFilterValues` 应用到目标字段。
- 没有匹配值时使用经源值集合确认不存在的唯一条件，由原生 AutoFilter 产生零行结果。
- 全部数据匹配时只清除目标字段条件，避免提交巨大值数组。
- 应用和清除均只操作目标 Field，不调用 `ShowAllData`，不关闭 `AutoFilterMode`。
- “清除本次过滤”只在当前 Add-in 会话中清除本工具最近处理的同一工作表、标题行和目标列。

## 已有筛选自动加载

窗口打开时只检查当前目标字段。仅当对应 `Filter.On` 为 `true` 时才加载；工作表仅显示筛选箭头、当前字段仍为全选时不加载整列数据。

eWorkHelper 每次应用后在 Add-in 运行时内存中保存工作簿、工作表、筛选区域边界、目标 Field、原始 Conditions、MatchMode 和目标 Filter 签名。再次打开同一字段时，只有上下文和签名仍一致才恢复原始条件与模式；任何上下文或 Filter 变化都会放弃旧状态。

无法确认来源的 Excel 原生筛选回退为当前可见结果：对目标 DataRange 调用 `SpecialCells(xlCellTypeVisible)`，逐 Area 批量读取 `Value2`，在 C# 内存中去除空值并使用不区分大小写集合去重，同时保留第一次出现的文本和顺序。回填模式固定为“等于”。零可见行时保持空文本并显示状态，不修改现有筛选。

读取过程不调用 `ShowAllData`，不临时取消任何 Filter，也不修改其他字段条件。

## 非破坏性保证

- 不修改单元格值或公式。
- 不创建辅助列、工作表或临时标记。
- 不直接修改行 Hidden 状态。
- 不清除其他字段已有的筛选条件。

## 已知限制

- 仅支持 Windows 桌面版 Excel。
- UI 和提示文本当前为中文。
- 不支持正则表达式或公式条件。
- 原生 `xlFilterValues` 的唯一值容量和性能受 Excel 版本及本机环境限制。
- 最近筛选状态仅保存在 Add-in 进程内，Add-in 卸载后不保留。
