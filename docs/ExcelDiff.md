> 状态：已完成 M1～M3.2 基础实现及本轮进度监控/行级状态增强；Excel 真机验收状态见文末。  
> 研究日期：2026-09-19。  
> 参考工程：`diff-excel/`，仓库 `https://github.com/zbuzhi/diff-excel`，审计 Commit `e99adcce958bc6adce56ce18b7b17082af153b6c`。

## 本轮增强设计（独立进度监控与行级状态）

本轮在既有 M1～M3 实现上采用最小增量：比较仍由专用 STA 线程中的独立 Excel 实例执行，核心仍按原始行列坐标比较；监控只读取托管快照，不访问 Excel COM。

### 设计与数据模型

- `ExcelDiffProgressMonitor` 使用 `Stopwatch` 和托管 `Timer`，从开始比较时启动，每秒生成快照；计时不依赖 Excel COM 或工作线程回调。快照包含任务 ID、阶段、操作、Sheet、已处理/总量（未知时为空）、单元格差异数、ADD/DEL/CHG 行数、状态、累计耗时、阶段耗时和最近实际进度时间。
- 工作线程只在阶段或批次边界发布真实进度；WinForms 通过 `BeginInvoke` 更新，旧任务 ID 的回调被丢弃，窗口关闭后监控和回调均安全停止。长时间没有进度只显示“当前操作耗时较长”，不自动判定卡死或终止 Excel。
- `ExcelDiffResult` 在托管比较循环中聚合稀疏的 `ExcelDiffRow` 状态：`Unchanged`、`Added`、`Deleted`、`Changed`。有效内容沿用 `ComparisonText` 空值语义，因此数字 0、布尔值、公式和错误值不会通过 `ToString` 或 `UsedRange` 重新判断。
- 结果副本中的参与比较 Sheet 先使用 Excel 原生列插入在最左侧新增 A 列，再将原始坐标统一映射为 `结果列 = 原始列 + 1`。高亮和基准值备注均使用该映射；未参与比较的 Sheet 不修改。

### 行状态语义与 DEL 策略

ADD/DEL/CHG 是相同行号的内容状态，不是行身份匹配：基准行全空而候选行有内容为 ADD；基准行有内容而候选行全空为 DEL；两侧有内容且存在任意单元格差异为 CHG；其余为空白。中间插行仍按坐标比较，不能宣称识别任意真实插入/删除。

结果继续以候选副本为内容基础，不恢复 DEL 行的基准内容，以免把“已删除”伪装成候选仍存在。启用基准备注时，原有差异单元格继续记录基准值；DEL 行的可追溯性由 A 列状态和这些基准值备注提供。未来如需完整的删除行明细，应增加独立明细输出，不改变本轮候选副本语义。

含 Excel Table/ListObject 的参与比较 Sheet 本轮拒绝插入状态列并保持源文件不变；工作表保护也继续拒绝。普通合并单元格交给 Excel 原生插列处理，并在集成测试中验证；图表、名称、打印区域、VBA 固定列引用等复杂对象不宣称跨 Office 版本完全保真。

### 验收标准与性能记录

自动化验收覆盖行状态聚合、0/空字符串/公式/错误值语义、坐标偏移、旧任务回调隔离以及独立计时；Excel 集成验收覆盖多 Sheet、A 列、高亮、备注、源文件 hash、取消清理和 COM 生命周期。性能记录区分托管比较、行状态聚合、插列/状态写入、差异标记/备注、保存和总耗时；没有 Excel 真机数据的项目不虚构性能结论。GUI 重绘仍依赖 WinForms 消息循环，独立计时不等于宿主 UI 在所有 COM 阻塞场景都可重绘。

本轮当前环境可复现的托管 smoke（Release，16 项通过；单次末次记录）为 100×20：约 0.17 ms、1000×20：约 3.96 ms、10000×20：约 9.22 ms；该数据包含行状态聚合，不能替代 Excel COM 插列、批量写入和保存的实测。VSTO/Excel 集成构建与真机性能因本机缺少 VSTO targets、Interop 和 Excel 宿主而未完成。

## 取消机制专项审计与修复设计

### 已确认的原始取消链路问题

GUI 的取消按钮只调用 `CancellationTokenSource.Cancel()`，服务原先仅在参数校验后、每个 Sheet 开始前、当前 Sheet 标记前和保存前检查令牌。`ExcelDiffEngine.Compare` 的逐单元格循环、行状态聚合、`ExcelDiffMarker.Apply` 的插列/状态/高亮/备注循环均没有检查点；因此取消发生在这些步骤中时，当前大段业务会继续执行，直到下一个 Sheet 或保存前检查点。单次 `Range.Value2`、`Workbook.SaveCopyAs`、`Workbook.Save` 和文件复制是同步操作，令牌不能安全地中断已经开始的 COM/文件调用。

### 修复后的调用链与检查点

取消请求记录为 `CancelRequested` 并立即将监控状态切换为 `Cancelling`；普通进度不再覆盖该状态。服务在每个工作簿打开/复制调用前后、每个 Sheet 读取阶段、托管比较的行和批次边界、行状态聚合、A 列插入前后、状态写入批次、高亮/备注批次、保存前后检查令牌。首次命中检查点记录 `CancelObserved`，随后记录 `BusinessStopped`，跳过剩余 Sheet、写入和发布。若同步 COM 调用已经开始，界面显示正在等待该调用安全返回；返回后立即检查，不启动下一项业务。

取消处理的 finally 只执行本任务拥有的工作簿关闭、COM 引用释放、独立 Excel 退出和临时文件删除。它记录 `CleanupStarted`、`CleanupCompleted`；工作线程退出后记录 `WorkerExited`。结果不会在取消路径中保存或发布；临时文件无论取消发生在比较、标记还是保存返回后均不发布并尝试删除。清理异常单独记录并继续相互独立的清理步骤。

每个任务的诊断轨迹只包含任务 ID、阶段、托管线程 ID、事件时间和相对取消耗时，不包含工作簿内容、路径或个人信息。该轨迹用于计算取消请求到感知、业务停止、清理完成和工作线程退出的时间。计时继续由独立 `Stopwatch/Timer` 提供，窗口关闭或旧任务回调不会访问已释放控件。

### 取消验收标准

- 托管大表比较在批次检查点停止，不继续处理剩余行或 Sheet。
- 标记/高亮/备注中途取消不处理后续批次、不保存、不发布不完整结果。
- 保存前取消不启动保存；保存已开始时不强行中断 Excel，等待返回后清理且不发布。
- GUI 顺序为“已收到取消请求，正在停止比较”→“正在清理临时文件和 Excel 资源”→“已取消比较”，取消按钮立即禁用，工作线程退出前不能再次开始。
- 自动化测试断言事件顺序、无输出文件、临时文件清理、任务可再次执行；Excel/GUI/VSTO 验收分别标记真实执行状态，不用令牌已设置代替业务停止证据。

本轮托管测试结果为 18/18，通过 20,000×20 合成数据在首个批次取消，末次运行“取消请求/测试注入到比较抛出取消”约 2.03 ms。该数值只代表不含 Excel COM 的托管引擎，不代表 `Range.Value2`、`Workbook.Save` 或独立 Excel 退出耗时；当前环境没有可执行的 Interop/VSTO/Excel 集成条件，因此这些阶段暂无实测取消延迟。

## 1. 结论摘要

### 1.1 可行性结论

可以在现有 C# + .NET Framework 4.8 + Excel VSTO 架构中复现参考项目已实际实现的核心行为，建议采用“纯 C# 比较模型 + Excel Interop 读写适配器 + WinForms 配置窗体”的方案。

可直接复现的核心包括：两个 `.xlsx` 文件、多个 Sheet 对、按坐标逐格比较、以待比较文件内容生成结果、差异填充色、旧值备注、选项颜色、结果日志以及原文件不被覆盖。VSTO 还可以自然补充已打开工作簿选择、状态恢复、COM 释放、取消和结果工作簿打开等能力。

不能在 M0 宣称“100% 等价”的原因：

- 当前环境未安装 Go，参考项目不能执行 `go test` 或 GUI 基准运行；运行结论仅来自源码和测试代码。
- 参考项目的实际默认 UI 路径是 `CompareFlexibleSheetPairs`，但旧的单 Sheet/多 Sheet 代码仍并存，部分选项与代码路径存在不一致。
- 参考项目的“格式保持”只是复制部分 OOXML 属性，不等同于完整工作簿克隆；公式、条件格式、图表、表格、数据验证、图片、批注冲突等没有完整处理证据。
- 新行/删行、主键匹配、行顺序无关比较、公式语义比较均未在源码中实现。
- Excel Interop 的实际性能、不同 Office 位数、保护工作表、现代线程批注及大文件行为必须在 M1/M4 真机验证。

因此，本功能应以“功能等价于参考项目已确认行为”为 P0，以 VSTO 安全性和 Excel 交互为 P1；行匹配等能力只能列为 P2 增强，不改变 P0 的坐标比较语义。

### 1.2 功能覆盖结论

本报告功能复现矩阵共列 20 项：源码已确认、计划完整复现（P0）13 项；源码已确认但参考实现存在缺陷或只能部分复现 4 项；VSTO 必须增加的进度/取消能力（P1）1 项；需要 M1/M4 运行实验后确认 2 项。另有 4 项明确未实现的 P2 增强，不计入上述 20 项矩阵。上述数字是审计和规划分类，不是“已完成数量”。M0 结束时仅文档交付，P0 尚未编码。

### 3.1 数据流

1. Fyne UI 选择旧文件和新文件；`GetSheets` 打开文件并返回 Sheet 名。
2. 用户添加 `SheetPair{SrcSheet, CmpSheet, DisplayName}`，或通过旧 checkbox/list 维护 `map[string]string`。
3. `compareFunc` 校验文件、对比组、输出目录和颜色，然后在输出目录创建带时间戳的子目录。
4. 比较器分别调用 `excelize.OpenFile` 和 `GetRows`，将每个 Sheet 表示为 `[][]string`。
5. 对两个二维数组取最大行数和每行最大列数；缺失项使用空字符串。
6. 对相同坐标执行字符串 `!=` 比较。差异单元格写入新值、设置填充色，必要时添加旧值备注并追加文本日志。
7. 输出文件保存为 `.xlsx`，差异日志保存为 `.txt`，成功对话框允许打开文件或目录。

## 4. 核心算法与实际行为

### 4.1 差异语义

实际算法是“同坐标、同字符串”的逐格比较：`maxRow = max(oldRows.Count, newRows.Count)`；每行取最大列数；缺失项按 `""`；`oldValue != newValue` 即差异。

因此文本、数字、日期等最终按 `GetRows` 返回的字符串比较；没有类型归一化、行键、列键、LCS、排序归一化或移动检测。末尾新增行/列会识别为新值对空值的差异，中间插入一行会使其后的同列单元格大面积被判为差异。没有“只比较公式文本”“只比较计算结果”“格式差异比较”。该语义是 P0 必须保留的基准；行匹配能力只能作为另一个显式 P2 模式。

### 4.2 输出方向与实际路径

`oldValue` 来自 `src`，`newValue` 来自 `cmp`，差异单元格写入 `newValue`，备注写入旧值，业务意图是“结果展示新文件，并在差异处标出旧值”。但实现路径不一致：默认 UI `multiSheetMode=false` 且自动创建 `sheetPairs`，实际调用 `CompareFlexibleSheetPairs`；该路径以新文件为格式基础。未被默认 UI 使用的 `CompareExcelFiles` 在格式保持路径复制旧文件；`CompareMultipleSheets` 还使用 map，顺序不稳定。

重写版本应统一以待比较/新工作簿为输出基础，保留新文件内容和格式，再高亮差异并记录基准/旧值。

### 4.3 格式保持范围

`copySheetContent` 明确复制列宽、行高、合并区域、读取到的单元格字符串值和非零样式 ID；差异单元格把样式 Fill 替换为用户颜色。没有证据表明公式及计算链、条件格式、数据验证、表格、筛选、图片、图表、页面设置、冻结窗格、隐藏状态、名称定义、线程批注和所有空但有格式单元格被完整复制。因此“格式保持”只能解释为有限属性复制；VSTO 方案应优先复制新工作簿后编辑。

### 4.4 批注、映射、错误和输出

- 差异且旧值非空时写传统备注，作者固定为 `Diff Excel`，AddComment 错误被丢弃；不读取或保护已有备注，也没有线程批注模式。
- 灵活对比组支持任意旧 Sheet 到新 Sheet 组合；只禁止完全相同的重复对，未禁止同一端 Sheet 多次映射。
- 输出名为 `【新】新Sheet <<【旧】旧Sheet`，没有 Excel 31 字符和非法字符校验。
- 旧 map 路径的 map 遍历顺序不稳定；`updateSheetUI` 为空，当前布局使用新的对比组列表。
- 源文件没有写回；格式保持先复制文件。多 Sheet 某 Sheet 读取失败时继续并可能保存不完整结果；没有统一临时文件清理和输出冲突确认。
- UI 过滤器只写 `.xlsx`；没有输出文件覆盖、占用、取消或真实进度机制。

| 领域 | 判断 | 边界 |
|---|---|---|
| 两个磁盘文件 | 可实现 | 只读打开源，复制后写结果；密码/锁定要预检 |

| 项目 | Excel Object Model | 独立文件库 |

## 11. M1 技术设计与测试计划

> 本节为 M1 开发前补充的设计记录。M1 完成后将继续在本节记录实际结果，不删除 M0 结论。

### 11.1 模块边界

M1 将核心拆为三层：

1. `ExcelDiffModels.cs`：只包含托管数据模型、坐标、单元格存在性和差异类型，不引用 Excel Interop、WinForms 或 Ribbon。
2. `ExcelDiffEngine.cs`：接收两个 `ExcelSheetData`，按参考项目的二维数组规则比较，返回结构化 `ExcelDiffResult`；缺失单元格和空字符串的比较值均规范为 `""`，因此二者按参考行为相等，但模型保留 `Exists` 元数据供输出/诊断使用。
3. `ExcelDiffInteropPrototype.cs`：在 Excel 宿主线程中批量读取 `Range.Value2`，通过内容边界而不是直接把 `UsedRange` 当作有效范围；提供最小差异写回能力。该层的 Excel 真机测试与核心单元测试分开记录。

核心模型使用 1-based Excel 坐标；读取数组由 Interop 适配层转换为 0-based 托管列表。差异类型只区分 `Added`、`Removed`、`Changed`；两侧比较文本都为空时不产生差异。类型、日期、公式和错误值先保留 `SourceKind`/原始值诊断信息，但默认比较键仍是适配层产生的字符串，以忠实复现参考项目 `[][]string` 语义，不引入公式专门模式。

### 11.2 接口草案

```text
ExcelDiffResult ExcelDiffEngine.Compare(ExcelSheetData baseline, ExcelSheetData candidate)
ExcelSheetData ExcelDiffInteropPrototypeReader.ReadWorksheet(Excel.Worksheet worksheet)
void ExcelDiffInteropPrototypeWriter.WriteDifferences(Excel.Worksheet worksheet, ExcelDiffResult result)
```

Interop 访问只在调用线程执行；不使用 `Task.Run`，不跨线程传递 RCW，不主动关闭或退出用户 Excel。所有由适配层取得的 Range/Worksheet/集合在 `finally` 中按逆序释放；宿主拥有的 Application 不释放。原型不修改 ScreenUpdating、EnableEvents、DisplayAlerts 或 Calculation。

### 11.3 M1 测试范围与验收

自动化核心测试使用合成内存模型，至少覆盖：完全相同、单/多点差异、旧侧有值/新侧为空、新侧有值/旧侧为空、不同边界、空 Sheet、数字/文本/日期/公式/错误值作为比较字符串、零值与文本 `"0"`、空字符串与缺失单元格、中间插行的坐标连锁差异、合并元数据不参与核心值比较。

核心测试必须断言差异数量、坐标、基准/待比较文本、差异类型和比较边界。Interop 测试单独检查批量读取、单元格/空区域、输出坐标、源文件不变、输出冲突和异常清理；没有 Excel 自动化条件时标记为未执行，不得由核心测试替代。

性能基准使用 100×20、1000×20、10000×20 的内存模型，分别记录比较耗时和托管内存；Interop 读取/输出耗时只有在真实 Excel 会话中测量后才记录。任何未实际测量的数据保持“未执行”。

## 12. M1 实际结果

### 12.1 已交付代码

- `ExcelDiffModels.cs`：托管单元格、Sheet、坐标、差异和结果模型。
- `ExcelDiffEngine.cs`：无 COM 依赖的按坐标逐格比较引擎。
- `ExcelDiffInteropPrototype.cs`：批量 `Range.Value2`/`Formula` 读取、内容边界查找和最小差异值写回原型；不包含高亮、备注、完整格式和文件打开编排。
- `tests/ExcelDiffCoreTests/ExcelDiffCoreTests.csproj`、`Program.cs`：独立 .NET 8 控制台测试项目，链接正式模型/引擎源文件，不进入 VSTO 发布工程。
- `eWorkhelper.csproj`：仅增加上述三个正式源文件的编译项，未修改 Ribbon、宿主生命周期或既有功能。

### 12.2 核心比较语义

核心使用每行实际长度计算局部比较列数，整体比较行数为两侧行数最大值，整体列边界为各行局部最大列数的最大值。缺失单元格和空字符串的 `ComparisonText` 都是 `""`，与参考 `GetRows` 循环一致；模型额外保留 `Exists`、`SourceKind` 和 `RawValue` 供诊断，但这些元数据不改变默认相等性。差异类型为 `Added`、`Removed`、`Changed`。

没有加入主键匹配、移动识别、行插入/删除归并或公式专门模式。测试已确认中间插行仍产生坐标错位后的连锁差异。

### 12.3 自动化测试结果

测试命令：`dotnet run --project tests/ExcelDiffCoreTests/ExcelDiffCoreTests.csproj --configuration Release`。环境为 Windows 11（OS build 26200）、.NET SDK 10.0.401，测试项目目标 `net8.0`。

结果：13 个测试全部通过，0 失败，0 跳过。断言覆盖无差异、单/多点差异、Added/Removed/Changed、空值/空字符串、零值与文本 `"0"` 的参考字符串语义、不同边界、空 Sheet、中间插行、参数错误和合并元数据不参与核心比较。

### 12.4 Excel Interop 原型结果

使用本机 Office 16 Excel 创建合成临时工作簿，在独立隐藏 Excel COM 实例中验证：

- 批量 `Range.Value2`/`Formula` 读取指定 Sheet；
- 旧值 `old`、新值 `new`、删除值和新增值共识别 3 个坐标差异；
- 将结构化结果写回候选文件副本，复核 `B1=new`、`A2=blank`、`B2=added`；
- 源工作簿未被写回，结果文件单独保存；
- 临时目录清理完成，测试创建的 Excel 实例已请求退出且之后未发现残留进程。

这是真实 Excel 读取/写回原型验证，不是完整结果功能验收。原型仍有明确限制：Value2 日期通常是 OADate 数值；错误值尚未转换为独立 `Error` 类型；写回使用比较字符串，可能改变数字/日期的原始类型；没有验证公式重算、格式、高亮、备注和复杂工作簿对象。

## 13. M1 遗留风险与 M2 建议

1. **值语义需要继续收敛**：参考项目是字符串数组，Interop Value2 对日期、错误值和公式的映射尚未达到可宣称等价；M2 先用合成 Excel 样本决定是否增加显示文本读取或显式值格式化适配，但不改变默认坐标算法。
2. **最小写回不是完整输出**：M2 应在临时副本上实现新文件基础、原格式保留、高亮和传统备注，并验证已有备注冲突策略。
3. **边界查找需要扩展测试**：当前使用 `Find("*", LookIn:=xlFormulas)` 避免直接把 UsedRange 当有效数据范围；需要补空公式、错误值、历史格式和隐藏行列样本。
4. **COM 生命周期需在 VSTO 入口验证**：原型释放了适配层拥有的 Range，但 M2/M3 还要验证 Workbook/Worksheet/集合的完整逆序释放，不得使用强制结束 Excel 进程兜底。
5. **性能数据不能外推**：核心算法规模表现正常，但 Excel COM 批量读取和写回仍无数据；M2 应先避免逐单元格读取，M4 再建立可比较基准。

M2 建议按以下顺序实施：结果副本和文件安全策略 → Value2/Formula/错误值测试矩阵 → 新工作簿内容复制与 Sheet 基础处理 → 差异高亮 → 旧值备注 → 日志和多 Sheet 服务编排 → 针对每项更新本矩阵。M3 再实现 Ribbon、WinForms 和进度取消，不提前在 M2 引入 GUI。

## 14. M2 技术设计与验收标准

### 14.1 结果与所有权

M2 服务统一以待比较/新工作簿为结果基础：磁盘文件使用字节复制，已打开工作簿使用 `SaveCopyAs`；结果副本在同目录生成唯一临时文件，所有映射成功、保存成功并可重新打开验证后才发布到用户目标路径。服务永不保存、关闭或退出用户传入的 Workbook/Application；只关闭本次通过 `Workbooks.Open` 创建的只读源和结果副本。输出与任一源路径相同时阻断；默认不覆盖已有输出，显式开启后才使用原子替换；含宏文件要求保持同扩展名。

### 14.2 统一业务接口

`ExcelDiffService.Compare(ExcelDiffRequest, IExcelDiffProgress, CancellationToken)` 是 M3 的调用入口。`ExcelDiffRequest` 包含基准/待比较工作簿来源、按顺序排列的 `ExcelDiffSheetPair`、`ExcelDiffOptions` 和 `ExcelDiffOutputOptions`；`ExcelDiffExecutionResult` 返回 `Completed/Cancelled/Failed`、总差异数、逐 Sheet 结果、日志、输出路径和异常。接口不接受 WinForms 控件。

### 14.3 类型与格式策略

比较键仍然是适配层生成的字符串，保持参考项目 `[][]string` 语义：公式默认比较缓存/Value2 结果，不比较公式文本；数值和数字文本最终按字符串键比较；Excel 错误码转换为 `#NULL!`、`#DIV/0!`、`#VALUE!`、`#REF!`、`#NAME?`、`#NUM!`、`#N/A`；带日期格式的数值按 Excel 序列值转换为确定的 ISO 文本，同时保留 RawValue、FormulaText、NumberFormat 和 SourceKind。该日期格式识别是适配层策略，不宣称完全等同所有区域化 Excel 显示文本。

结果不重新写入非差异单元格。高亮和备注直接作用于候选工作簿副本，因此公式、错误值、数字类型、宏、合并、行列尺寸和其他原生 OOXML 对象由 Excel 副本自然保留。M2 明确验证字体/填充/边框/数字格式/行高/列宽/合并/隐藏状态等关键属性；条件格式、数据验证、图表、命名区域等只记录复制副本结果，未逐项验证不得宣称完整支持。

### 14.4 标记与备注策略

差异高亮默认使用 `Color.Red` 的纯色填充，只改变目标差异单元格的 `Interior.Color`；合并区域差异不拆分合并，改为高亮整个 MergeArea，并在左上角处理备注。备注默认关闭以匹配参考项目；开启时保存基准侧 `ComparisonText`，空基准值不写备注。已有传统备注不覆盖，使用 `[ExcelDiff]` 分隔追加。线程批注不作为 M2 兼容目标。

### 14.5 取消、日志与验收

取消令牌只在打开、每个 Sheet 读取/比较/标记和保存前的安全检查点生效；取消后停止后续 Sheet，关闭结果副本并删除临时文件，不修改 Excel 全局状态。进度只报告阶段、已完成 Sheet、总 Sheet 和差异数，不伪造百分比。日志不写完整单元格内容、凭据或完整用户路径，只记录阶段、Sheet 序号、差异数量、状态和异常类型。

M2 验收要求：M1 13 项测试继续通过；新增类型/格式/高亮/备注/映射/输出冲突/取消测试具有明确断言；真实 Excel COM 至少完成多 Sheet、源文件不变、候选副本可打开、差异标记、已有备注追加、合并区域不拆分、临时文件清理和失败路径；Go 原版仍不可运行时，必须标记为源码行为一致性检查而非原版对标通过。

## 18. M3.1 阻断修复与验收记录

### 18.1 签名根因

项目并非没有签名配置：`eWorkhelper.csproj` 保留了 `ManifestKeyFile=eWorkhelper_TemporaryKey.pfx` 和开发证书指纹，`.gitignore` 的 `*.pfx` 规则避免私钥进入 Git。失败原因是当前用户证书存储在前一次环境中缺少该指纹对应的私钥证书，而不是 C# 编译失败。当前工作区发现对应 PFX 未被 Git 跟踪，使用现有本地开发证书完成了隔离构建；不改变正式发布签名要求，不记录密码，不提交 PFX。

### 18.2 COM 遗留进程调查

发现 PID 3484，启动命令为 `EXCEL.EXE /automation -Embedding`，无主窗口，唯一工作簿曾位于 `AppData\Local\Temp\eWorkHelper-ExcelDiff-*`，因此确认属于测试实例。已通过 COM 正常关闭其工作簿并调用 `Application.Quit`；复查时工作簿数量为 0，但进程仍存活，未使用强制终止。该进程应在后续 Excel/VSTO 清理后由用户或环境处理。M3.1 同时修复了窗体对宿主已打开 Workbook RCW 的错误释放：窗体只借用并清空引用，不调用 `FinalReleaseComObject`，由宿主负责其生命周期。

### 18.3 取消执行方案

根因是原窗体在 Excel 宿主 UI 线程同步调用 `Compare`，COM 调用期间 WinForms 消息循环无法处理取消按钮。现在窗体将已保存来源转换为文件路径，在专用 `Thread`/STA 中创建并拥有独立的隐藏 Excel 实例；该线程创建、使用和退出自己的 Excel RCW，不跨线程传递宿主 Application/Workbook。进度回调通过 `BeginInvoke` 回到 UI 线程，取消令牌由 UI 线程触发并在服务安全检查点确认。未保存工作簿仍要求先保存，避免把不确定的宿主快照跨线程传递。

该方案不是 `Task.Run` 包装 COM，也不使用 `Application.DoEvents` 或 `Thread.Abort`。窗口关闭在任务完成/确认取消前阻止，取消请求、服务返回取消和资源清理分别反馈。

## 20. M3 操作优化设计与验收范围

Ribbon 点击时在宿主线程读取 `ActiveWorkbook` 的完整路径、名称、已保存状态及文件身份，固定为本窗口的基准；不长期保存 Workbook RCW。无活动工作簿、未落盘或有未保存修改时提示用户先保存，不由插件保存。窗口只读显示完整基准路径；重新选择基准需关闭窗口并在目标工作簿中重新点击 Ribbon。候选保留已打开/磁盘文件选择，已打开但有未保存修改时拒绝读取过期磁盘文件。基准与候选同一路径（Windows 不区分大小写）时拒绝比较。

开始前重新核对基准工作簿仍在原 Excel 实例中打开、路径及已保存状态不变，磁盘文件仍存在且没有在窗口期间变更；若关闭、另存、修改、保存后的映射可能过期，要求重开窗口。候选的打开状态及磁盘路径在执行前也重新核对。仅向专用 STA 比较线程传两个文件路径，不传宿主 COM 对象。基准 Sheet → 候选 Sheet、候选副本高亮和基准值备注语义保持不变。候选变更时清空映射并重新加载。

### 20.1 实现与安全边界

`MainRibbon` 在按钮回调中调用 `ExcelDiffWorkbookIdentity.CaptureActive`，读取活动 Workbook 的完整路径、COM 身份和磁盘 SHA-256 快照，立即释放本次获取的临时 RCW 引用。`ExcelDiffForm` 只保存路径/身份值，不持有宿主 Workbook；只读文本框展示可复制的完整路径。开始前 `Validate` 在宿主线程逐项核对原工作簿仍打开且 COM 身份不变、未有未保存修改、磁盘内容与启动时一致；候选若在同一 Excel 实例打开，也检查 `Saved`。路径比较使用 Windows 不区分大小写的完整路径，不依赖工作簿显示名称。基准已保存但在窗口期间重新保存也会阻止执行，避免继续使用过期 Sheet 映射；需要关闭并重新从目标工作簿进入。不同目录的同名文件身份虽可区分，但 Excel 不能在同一实例同时打开两者；当前服务在同一专用实例中读入两侧，故明确拒绝并要求先为候选另存为不同文件名，不产生误比较结果。

Sheet 枚举先检查当前 Excel 已打开的文件；已有 Workbook 仅借用引用，不关闭，磁盘文件才由窗体临时打开并负责关闭。候选选择变化时清空映射。`ExcelDiffService`、引擎、候选副本高亮及基准旧值备注未更改。独立 STA 线程仍只收文件路径、进度及取消令牌，不收宿主 RCW。
