# 回归测试清单

## 自动验证

每次影响代码、项目结构、Ribbon、资源或版本元数据的变更，至少执行：

1. Debug / Any CPU Rebuild。
2. Release / Any CPU Rebuild。
3. 确认 Error 和 Warning 数量。
4. 检查项目引用、Ribbon Designer、`.resx`、ThisAddIn 主机项和生成代码均正常编译。
5. 如存在自动化测试项目，运行全部相关测试；当前仓库尚无独立自动化测试项目。

完整 VSTO 清单构建需要在本地进程或受保护的发布环境中临时提供签名配置，不得把证书信息写入仓库。

## VSTO 基线

- Visual Studio F5 能启动 Excel。
- Add-in 能正常加载。
- `eWorkHelper` Ribbon Tab 正常显示。
- “数据工具”Group 和“批量过滤”按钮正常显示。
- 点击按钮可获取当前 Excel 上下文并打开批量过滤窗口。

上述链路曾完成过人工验证。凡是修改 ThisAddIn、Ribbon、项目引用、资源或启动配置，都必须重新人工验证受影响链路。

## 批量过滤回归场景

- 四种模式互斥，默认选中“包含”。
- 单条件、多条件、重复条件、空行、中英文、英文大小写、数字和空单元格。
- 等于/不等于、包含/不包含的互补语义。
- Excel ListObject。
- 已有 AutoFilter 的普通区域。
- 无 AutoFilter 时选择标题行、取消选择、跨行错误选择、标题上方存在说明内容。
- 无匹配、全部匹配、大量唯一值。
- 其他字段已有筛选时应用和清除目标字段。
- 连续多次应用以及“清除本次过滤”。
- 工作表受保护、没有工作簿、无有效活动单元格等错误路径。

## 非破坏性检查

- 单元格值、公式和工作表结构没有变化。
- 未创建辅助列、临时工作表或额外 Excel 进程。
- 未直接修改行 Hidden 状态。
- 其他字段筛选条件保持不变。
- `ScreenUpdating` 和 `EnableEvents` 在成功及异常路径后均恢复。
