# 回归测试清单

## 自动验证

每次影响代码、项目结构、Ribbon、资源或版本元数据的变更，至少执行：

1. Debug / Any CPU Rebuild。
2. Release / Any CPU Rebuild。
3. 确认 Error 和 Warning 数量。
4. 检查项目引用、Ribbon Designer、`.resx`、ThisAddIn 主机项和生成代码均正常编译。
5. 如存在自动化测试项目，运行全部相关测试；当前仓库尚无独立自动化测试项目。

完整 VSTO 清单构建需要在本地进程或受保护的发布环境中临时提供签名配置，不得把证书信息写入仓库。

## VSTO 基线

- Visual Studio F5 能启动 Excel。
- Add-in 能正常加载。
- `eWorkHelper` Ribbon Tab 正常显示。
- “数据工具”Group 和“批量过滤”按钮正常显示。
- “数据工具”Group 中“取消合并并填充”作为第二个正式大按钮正常显示，无 Test、Demo 或 Debug 入口。
- 点击按钮可获取当前 Excel 上下文并打开批量过滤窗口。
- “关于”Group 位于 `eWorkHelper` Tab 的最末端，按钮可打开简介并显示完整四段产品版本。
- 关于窗口版本来自 `AssemblyInformationalVersion`，与生成程序集 ProductVersion 一致。

上述链路曾完成过人工验证。凡是修改 ThisAddIn、Ribbon、项目引用、资源或启动配置，都必须重新人工验证受影响链路。

## 批量过滤回归场景

- 四种模式互斥，默认选中“包含”。
- 单条件、多条件、重复条件、空行、中英文、英文大小写、数字和空单元格。
- 等于/不等于、包含/不包含的互补语义。
- Excel ListObject。
- 已有 AutoFilter 的普通区域。
- 无 AutoFilter 时选择标题行、取消选择、跨行错误选择、标题上方存在说明内容。
- 无匹配、全部匹配、大量唯一值。
- 其他字段已有筛选时应用和清除目标字段。
- 连续多次应用以及“清除本次过滤”。
- eWorkHelper 创建的“包含”和“不包含”筛选重新打开后恢复原始条件及模式，而不是匹配结果列表。
- Excel 手动多选筛选重新打开后加载当前可见唯一值，保持首次出现顺序，并自动选择“等于”。
- 当前字段只有筛选箭头但 `Filter.On` 为 false 时不加载整列。
- 多字段同时筛选时，只按当前整体可见结果读取目标列，不清除或改写其他字段。
- 当前目标 Filter 为零可见行时不抛异常、不清除筛选，并保持空文本。
- 工作表受保护、没有工作簿、无有效活动单元格等错误路径。

## 非破坏性检查

- 单元格值、公式和工作表结构没有变化。
- 未创建辅助列、临时工作表或额外 Excel 进程。
- 未直接修改行 Hidden 状态。
- 其他字段筛选条件保持不变。
- `ScreenUpdating` 和 `EnableEvents` 在成功及异常路径后均恢复。

## 取消合并并填充回归场景

- 单个纵向、横向以及多行多列矩形合并区域。
- 同时选择多个连续合并区域；大范围混合普通单元格与多个合并区域；Ctrl 多选多个 Areas。
- Selection 只覆盖 MergeArea 的部分单元格时，处理完整 MergeArea。
- 同一 MergeArea 被多个单元格或重叠选区命中时只执行一次。
- 文本、数字、日期、布尔值、空值和公式；空值不写成字符串，公式不固化为计算结果。
- 普通单元格保持不变；没有合并单元格时不修改工作表并给出简短提示。
- A1:Z5000 等大范围中的稀疏合并区域，确认执行时间可接受且没有无边界逐单元格扫描。
- 字体、字号、颜色、填充、边框、数字格式、对齐、行高和列宽未被功能主动改写。
- 成功和异常路径后 `ScreenUpdating`、`EnableEvents` 保持用户操作前的状态；失败时显示简短错误信息且异常不被静默吞掉。
